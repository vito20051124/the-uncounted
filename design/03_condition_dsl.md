# 03 · 條件求值器與內容資料格式

> 上位：`00_pillars.md` · `01_architecture.md`（尤其 §11.1 紀律 7：**所有條件走同一個求值器**）

---

## 0. 為什麼這份文件必須先於任何事件

獨立壓力測試把這件事列為**最可能也最貴的失敗模式**：

> DSL 一開始太窮，寫到第 6 個事件就開始在資料裡塞邏輯。
> 症狀：`requires: { custom: "hasBandageAndNotRaining" }`、一次性旗標 `flags: { ev_07_done: true }`、同一事件複製三份只為改一個數字。
> **一旦開始，「內容零邏輯」就破功，而那是本作對 DoL 的核心改進之一。**

**因此本文件的產生順序是刻意的**：

```
先用純中文寫 12 個事件的條件敘述
   ↓
從敘述反推「至少需要哪些謂詞」
   ↓
才定 DSL
```

**不是先設計 DSL 再套事件。**

## 2. 從敘述反推：必要謂詞清單

逐句拆解上表，得出**最小但夠用**的謂詞集。每一條都指得出是哪個事件逼出來的。

| 謂詞 | 形式 | 由哪個事件逼出 |
| :-- | :-- | :-- |
| **地點** | `at: <nodeId>` 或 `at: [<nodeId>, ...]` | 1,2,3,6,8,9,10,12 |
| **在某條邊上** | `onEdge: <edgeId>` | 7 |
| **時段（含跨午夜）** | `hours: [from, to]` —— **`from > to` 即視為跨午夜** | 1,3,7 |
| **潮汐** | `tide: "rise" \| "ebb"` | 2,10 |
| **潮汐剛轉變** | `tideJustTurned: "rise" \| "ebb"` | 10 |
| **需求數值比較** | `needs.<key>: "<15"` —— 支援 `< <= > >= = !=` | 1,4 |
| **物品持有** | `has: { item: <itemId>, min: <n> }` | 9 |
| **傷病查詢** | `injury: { infected?: bool, minSeverity?: n, minAgeDays?: n, untreated?: bool }` | 5,6 |
| **★ 買不起** | `cannotAfford: <itemId>` ／ `canAfford: <itemId>` —— **引用物價表求值，不是常數** | 6,12 |
| **知識** | `knowsRoutes: ">=1"` 或 `knowsRoute: <edgeId>` | 3 |
| **聲望** | `rep: { faction: <id>, op: "<", value: 20 }` | 8 |
| **節點屬性** | `nodeSecurity: ">=3"` | 11 |
| **一生一次** | `once: true` | 9,12 |
| **冷卻** | `cooldownDays: <n>` | 8 |
| **行動觸發** | `onAction: <actionId>` | 11 |
| **布林組合** | `all: [...]` ／ `any: [...]` ／ `not: {...}` | 全部 |

> **這 16 個謂詞就是 P0 的全部。** 任何寫不出來的事件，**先問是不是缺謂詞，而不是先加 `custom` 逃生門**——`custom` 一旦開放就再也關不上。

## 3. DSL 規格

### 3.1 求值入口（唯一）

```ts
evaluate(cond: Cond, ctx: Ctx): boolean
resolve(expr: Expr, ctx: Ctx): number     // 供 cost / gain / chance 用
```

**紀律 7：全引擎只有這一個入口。** 禁止任何地方寫 inline 的 `if (state.pc.needs.satiety < 20)`。

### 3.2 比較運算子的寫法

一律寫成**字串前綴**：`"<15"` / `">=30"` / `"=0"` / `"!=0"`。
理由：在 JSON／YAML 裡可讀、可 diff、不需要巢狀物件包一層 `{ op, value }`。

### 3.3 ★ 跨午夜時段（最容易寫錯的一條）

```
hours: [5, 8]    → 05:00 ≤ t < 08:00        （一般區間）
hours: [22, 4]   → 22:00 ≤ t < 24:00  或  00:00 ≤ t < 04:00   （跨午夜）
```

**判定規則**：`from < to` 用一般區間；**`from > to` 一律視為跨午夜**。
天真的 `t >= from && t < to` 在第二種情況會**永遠為假**——這是壓力測試特別點名的坑。

### 3.4 ★ `cannotAfford` 為何必須是謂詞而不是常數

事件 6 的條件是「錢不夠買那一劑藥」。若寫成 `purse.copper: "<12"`，則**藥價一改，所有事件都要改**。

```yaml
# ✗ 錯：把物價寫死在事件裡
requires: { "purse.copper": "<12" }

# ✓ 對：引用物價表
requires: { cannotAfford: "item-salve" }
```

> **「窮」不是一個數字，是一個關係。** 這條謂詞是本作主題在資料層的具體表達。

### 3.5 完整事件範例

```yaml
id: ev-quays-dayhire
where: { at: bh:quays }
when:  { hours: [5, 8] }
requires:
  all:
    - { "needs.stamina": ">30" }
    - { not: { injury: { minSeverity: 2 } } }
cooldownDays: 0
weight: 12
tell: 監工站在人群前，先挑手上有繭的。
text: |
  ...
choices:
  - label: 排隊等挑
    cost: { minutes: 45, stamina: -3 }
    outcomes:
      # 被挑上的機率受 hygiene 調節：基礎 0.6，每低於 50 一成扣 0.05
      - chance: { base: 0.6, modBy: "needs.hygiene", curve: "linear", at50: 0.6, at0: 0.35 }
        then: { job: job-quays-dayhire }
      - else: { text: 今天輪不到你。, cost: { minutes: 0 } }
  - label: 算了
    cost: { minutes: 5 }
```

### 3.6 `src` 出處標記（紀律：可查詢的真實性）

`data/**` 內**每一個數值**都要帶出處，值只有三種：

| 前綴 | 意義 | 範例 |
| :-- | :-- | :-- |
| `canon:` | 直接抄自世界正典 | `canon:brinehaven/districts.md#碼頭區` |
| `derived:` | 由正典數值推導 | `derived:通鋪 2/3/4 內插` |
| `invented:` | 憑設計判斷填的 | `invented:P0 平衡，待試玩校正` |

建置期統計三者比例，**P0 目標 `invented` ≤ 20%**。

> **這比任何平衡表都有用——它讓「哪裡是假的」變成可查詢的，而不是靠記憶。**

## 4. 反面清單（出現任何一項即為破功）

| 禁止 | 為什麼 |
| :-- | :-- |
| `custom: "<函式名>"` | 逃生門一開就關不上，「內容零邏輯」立刻破功 |
| 一次性旗標 `flags: { ev_07_done: true }` | 用 `once` 與 `cooldownDays` 表達，不要自建旗標命名空間 |
| 同一事件複製三份只為改一個數字 | 用 `weight` 與 `outcomes` 的機率分支表達 |
| 把物價寫死在事件的數值比較裡 | 用 `canAfford` / `cannotAfford` |
| 在引擎任何地方寫 inline 條件判斷 | 紀律 7：入口只能有一個 |
| 小數分鐘 | 紀律 8：時間一律整數分鐘 |
| 浮點金帝 | 紀律 3：金錢一律以銅為整數 |
